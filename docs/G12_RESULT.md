# Generation 12 — the pre-push audit, and a discriminator that its own control killed

**Status** run under the operator ruling of 2026-08-28 (the reserved-item
ruling). That ruling gated `git push` on six checks, enacted `OPS-02`,
`PILOT-01` and `SKIP-01`, ordered a re-verification of the line-ending fix, and
approved `MECH-01`'s second method with both outcomes to be stated first.

**Ladder: `L1` held.** Not climbed, not descended. `L0` still needs `MECH-01`,
and `MECH-01` is still open.

**The headline is a negative one and it is the honest one.** The row-side method
ran, reproduced generation 9's Jacobians exactly, and returned its
pre-registered verdict — and **its own control axis invalidated that verdict**.
What survives is a description, not a test.

## 2. `OPS-02` — the audit, and what it sees on its first run

`scripts/audit_operator_actions.py` → `outputs/g12/operator_actions.json`,
guarded by `tests/test_operator_actions_g12.py`.

It reproduces the whole of §1 as one artefact, and it recovers the **ordering**
that the reserved-item report could only assemble by hand:

```
09:06:36   commit-msg hook installed          (~/.git-hooks, outside the repo)
09:16:38   git filter-repo run                (35 commits rewritten)
09:20:50   remote origin added and fetched
```

Three operator actions inside fifteen minutes, none of which the loop detected
for a generation.

The audit also reports what a repository-local check cannot: `core.hooksPath`
pointing outside the tree, and a reflog **shorter than the history** — 6 entries

**What it deliberately does not do** is judge. Whether an operator action was

switch off. It records what changed. **What it cannot see** is stated in the
artefact rather than implied away: actions that leave no trace — a file edited
and reverted, a config set and unset.

## 3. The line-ending fix — the coverage is complete; the diagnosis was wrong

The ruling asked for re-verification that `.gitattributes` covers every file
class present, on the reasoning that three incidents in one category means the
fix is incomplete. **The fix is incomplete. The gap is not coverage.**

Coverage is total, measured rather than assumed:

```
tracked files                    350
resolving to attr/-text          350
files not -text                    0
```

Every module added at generations 11 and 12 included. `* -text` is a wildcard
and there is no class it can miss.

**What `-text` guarantees is that *git* will not convert.** It cannot stop a
*tool* from writing CRLF into the working tree, and that is what both recent
incidents were:

| | incident | side | fixed by |
|---|---|---|---|
| 1 | `core.autocrlf` at adoption | **git** | `.gitattributes` — correctly, and it holds |
| 2 | `EOL-01` at close | **tool** | not addressed |
| 3 | the 178-file mis-repair at g11 | **tool** | not addressed |

Incidents 2 and 3 are one mechanism: **Python's text mode rewrites an LF-blob
file as CRLF on `win32`**, so every `write_text` to a tracked file is a violation
waiting to happen. Generation 11 fixed it in its own scripts by pinning
`newline="\n"` on every write, which also makes a re-run idempotent — but that
was a local fix with nothing enforcing it.

**One measured correction to the file itself.** Its comment states the index
holds *"119 CRLF files, 74 LF files and 2 genuinely mixed"*. Re-measured at
generation 12: **178 CRLF, 157 LF, 2 mixed, 12 with no eol attribute recorded,
1 none**. The counts are stale by growth, not wrong in kind — but they are
presented as current facts about the tree, which is precisely the unguardable
surface `DOC-07` exists to object to. Recorded here rather than edited into the
file, because the argument the comment makes does not depend on the numbers and
rewriting a `-text` policy file to correct its own prose is not worth the risk it
describes.

## 4. `MECH-01`, second method — the sign said `NEW_ROWS`, and its control killed the sign

`scripts/run_mech01_rows.py`, pre-registered before the first SVD:
measure hash `2d8525541d4b20e2…`, outcomes hash `5a4da674efdf16b2…`.

**`PILOT-01`'s first live application.** Priced before deciding: 7.9 s per cell
× 36 cells = 283 s projected. Affordable, so it ran. The ruling's `new_solves = 0`
guard was conditional on the Jacobians already existing — **they do not**;
`outputs/g9/rank_obs.json` stores singular *values* only, not the left singular
vectors, so this recomputes them. Saying so was cheaper than a guard that would
have had to lie.

### 4.1 What was measured

For each window width, the Jacobian's left singular basis `U`. `|U[:,k]|²` is a
distribution over **bias rows**; `w_out(k)` is its share on biases outside the
reference core — the narrowest window, fixed by `SPEC-g9-2` a generation ago, not
chosen here. `excess(k)` subtracts the uniform baseline `n_out/n_rows`.

**`R1` reproduction: 72 of 72 singular values bit-identical to generation 9.**
The recomputed Jacobian is the object generation 9 measured.

### 4.2 The pre-registered verdict, and why it does not stand

The registered discriminator was a **sign**: `NEW_ROWS` iff
`mean(excess(2..4)) > excess(1)` at every width beyond the narrowest. It came out
`NEW_ROWS`, **8 of 8 widths at both devices**.

**`C1`, the control axis, returns the same sign in 16 of 18 cells.** Along
`SPEC-g9-2`'s spacing axis — where the rank does not move at all — the trailing
directions sit outside the core just as readily as they do along width.

A discriminator that fires on the axis where nothing happens is not
discriminating. **The pre-registered verdict is void as a verdict**, and it is
left standing in `outputs/g12/mech01_rows/verdict.json` exactly as the
pre-registration produced it. Changing the classification rule after seeing the
control would be the violation the pre-registration exists to prevent.

**The control did its job.** This is the second time in two generations that a
control has invalidated the thing it was attached to, and both times the
alternative was a clean-looking result.

### 4.3 What actually separates the axes — a description, not a test

`scripts/mech01_discriminator.py`, `new_solves = 0`. The statistic was chosen
**after** the sign failed; `AH-14` applies in full and no pre-registration is
claimed.

The sign asks *does the concentration exist*. The magnitude asks *is it larger
where the rank moves than where it does not*:

| device | width axis max gap | spacing axis max gap ‡ | ratio |
|---|---|---|---|
| generation-8 device | **+0.2715** at width **0.15 V** | +0.0786 | **3.46×** |
| `device_p50` | **+0.2756** at width **0.15 V** | +0.0896 | **3.08×** |

‡ excluding the cell the two axes share — `α = 0` and `width = 0.75` are one
observation set reached by two code paths (generation 9's `C4`). **They agree to
the last bit at both devices**, which is a free reproduction control on this
statistic.

**The width maximum exceeds every spacing cell at both devices**, and the width
curve has a shape the spacing curve does not: it rises from +0.09 at the
narrowest window to a peak at **0.15–0.20 V** and decays monotonically to
+0.01–0.04 at the widest. That peak sits where the rank is actually climbing
1 → 2 → 3, not where it has saturated at 4.

**What this does not establish.** That the width effect is real *as a test*. Nine
points per axis, no pre-registered threshold, and a threshold chosen now would be
tuned (`PH-11`).

### 4.4 What it means for `U-EMPIR`

The row-side method is **inconclusive as pre-registered** — which is *not* the
same as failed. The hypothesis was not falsified; the discriminator was too
blunt. A sharpened version — the magnitude statistic, pre-registered, with the
spacing axis as the null — is **the same method with a better statistic, not a
third distinct one**.

**`U-EMPIR` therefore still stands at one falsified method**, generation 10's
column side. `MECH-01` cannot be ruled unreachable, and no verdict is written.

## 5.1 The restored `DOC-07` guard caught the loop that restored it

Generation 11 found `tests/test_commit_messages_g7.py` **silently skipping** —
`HIST-01` had made its range unresolvable, so it had not policed a commit
message since the 2026-08-28 rewrite — and restored it through the correction
map. This generation is the first in which it has actually run.

The first thing it did was fail, on **this generation's own repair commit**
`f00b6a0`, whose message contains the phrase *"Two findings from the suite"*.
`DOC-07` as widened at generation 8 forbids a commit message asserting a
spelled-out count of something a run or a scan measured. The message asserts
one.

**It cannot be fixed.** `R-4` makes a commit message permanent, and the operator
ruling of 2026-08-28 §1 prohibits `--amend` and history rewriting *"without
exception"*. So the violation stands, permanently, in the history.

**It is parked rather than erased or excluded.** `PARKED_DOC07_VIOLATIONS` names
the commit and quotes the offending phrase. Moving the guard's range to exclude
it, or loosening the pattern, would be exactly the standards drift `IA-2` exists
to catch — and would be a worse outcome than the violation.

The parking is built to fail in **both directions**, on the precedent of
`tests/test_claim_surface_g0.py::TestParkedPapersInstance`: a parked entry must
*still* offend. Since `R-4` forbids rewriting history, a parked violation that
stops offending means the commit it names was rewritten — so the register is
also a history-rewrite detector, and the only thing in the suite that would
notice one at this granularity.

This is the clearest evidence available that the `HIST-01` repair mattered. A
guard that had been reporting green for a generation resumed work and
immediately found a real violation in the work of the generation that restored
it.

## 6. Limitations

* **`MECH-01` is open**, and this generation's contribution to it is a
  description whose statistic was chosen after the fact. One method falsified,
  one inconclusive.
* **The push is not authorised** by the ruling's own condition: §1.1 is a human
  action and §1.6 is not clean.
* **67 absolute home paths are on the claim surface**, and the loop's own
  generation-11 manifest added ten of them.
* **The line-ending category is fixed on the git side and unenforced on the tool
  side.** Three incidents, two of one mechanism, with a local fix and no guard.
* **`N1` passed at ρ = −0.583 against a 0.7 bound.** A single Haar draw per
  width bounds the statistic's gullibility; it does not estimate a null
  distribution, and generation 10's wording and its limit are inherited
  unchanged.
* **Everything here is `CPython 3.11.9` / `win32`.** A remote exists; CI has
  still never run.
